# اتصال زرین‌پال

پرداخت با API v4 زرین‌پال و فقط از سمت سرور انجام می‌شود. مبلغ سفارش در فروشگاه به تومان نگهداری می‌شود و برای درخواست و تأیید زرین‌پال، در ۱۰ ضرب و به ریال تبدیل می‌شود.

## محیط محلی

در فایل `.env.local` این متغیرها را تنظیم کنید. فایل `.env.local` در Git نادیده گرفته می‌شود؛ شناسه پذیرنده را در فایل عمومی یا کد قرار ندهید.

```env
ZARINPAL_MERCHANT_ID=شناسه-پذیرنده-پنل-زرین‌پال
ZARINPAL_CALLBACK_BASE_URL=https://آدرس-عمومی-تونل
```

زرین‌پال باید بتواند Callback را از اینترنت فراخوانی کند. اگر برای توسعه محلی از تونل عمومی استفاده می‌کنید، مقدار `ZARINPAL_CALLBACK_BASE_URL` را روی origin عمومی تونل، مانند `https://example-tunnel.example`، قرار دهید؛ مقدار آن نباید `localhost` باشد. مسیر Callback را برنامه به این origin اضافه می‌کند. اگر تونل عوض شد، مقدار متغیر را هم به‌روز کنید.

`NEXT_PUBLIC_SERVER_URL` برای Callback زرین‌پال استفاده نمی‌شود. این متغیر را از تنظیمات عمومی حذف نکنید اگر بخش دیگری از سایت به آن نیاز دارد؛ فقط برای اتصال زرین‌پال، `ZARINPAL_CALLBACK_BASE_URL` را تنظیم کنید.

## محیط Production در Liara

در متغیرهای محیطی سرویس Liara این موارد را قرار دهید:

```env
ZARINPAL_MERCHANT_ID=<secret>
ZARINPAL_CALLBACK_BASE_URL=https://viora-store.ir
```

`ZARINPAL_MERCHANT_ID` را به‌عنوان Secret ثبت کنید. پس از تغییر متغیرها، سرویس را با تنظیمات جدید راه‌اندازی یا Deploy کنید. در پنل پذیرنده زرین‌پال نیز دامنه `viora-store.ir` را ثبت و تأیید کنید. اگر `ZARINPAL_CALLBACK_BASE_URL` تنظیم نشده باشد، کد از دامنه ثابت `https://viora-store.ir` استفاده می‌کند؛ با این حال در Liara آن را صریحاً تنظیم کنید.

Callback به این مسیر می‌رسد و شناسه سفارش را به‌صورت query parameter دریافت می‌کند:

`https://viora-store.ir/api/payments/zarinpal/callback?orderId=...`

## فعال‌سازی و آزمون

روش پرداخت `ZarinPal` را در تنظیمات مدیریت فروشگاه فعال کنید. سفارش‌های قدیمی تنظیمات را خودکار تغییر نمی‌دهیم؛ روش را از پنل مدیریت اضافه و ذخیره کنید. سفارش‌های جدید بر اساس قیمت و موجودی MongoDB ساخته می‌شوند.

برای آزمون، یک سفارش کم‌مبلغ ایجاد کنید و هم بازگشت موفق و هم انصراف/لغو را بررسی کنید. در Callback با `Status=NOK` پرداخت ناموفق می‌ماند و Verify انجام نمی‌شود. با `Status=OK` سرور مبلغ همان سفارش را دوباره به ریال تبدیل و از API زرین‌پال Verify می‌کند. فقط کد Verify برابر 100 یا 101 همراه با شناسه مرجع معتبر، سفارش را پرداخت‌شده می‌کند. Callback تکراری نباید سفارش را دوباره تغییر دهد و شناسه پیگیری در `paymentRefId` ذخیره می‌شود.
